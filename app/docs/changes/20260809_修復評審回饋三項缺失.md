# 20260809_修復評審回饋三項缺失

## 變更摘要

Hackathon 結果公布後,主辦方分享了評審的具體回饋(CVI/CVA 20.3/30、Build Quality 16.3/25),指出兩類具體、可定位到程式碼的缺失。這次照優先順序修復其中三項(第四項「合約地址沒附 Explorer 連結」判斷為低優先,暫不處理)。

## 變更內容

1. **Admin API 沒有伺服器端驗證**——目前登入只在 `/api/auth/login` 檢查一次密碼,之後所有 `/api/admin/**` 路由完全不驗證呼叫者身分,只靠前端 `RoleGuard`(可被繞過)。新增真正的伺服器端 session:
   - `lib/auth/session.ts`:用 `SESSION_SECRET` 簽署/驗證 session token(HMAC-SHA256,含 8 小時過期)
   - `lib/auth/requireRole.ts`:API route 用的權限檢查 helper
   - `/api/auth/login` 登入成功時額外設一個 httpOnly cookie
   - 新增 `/api/auth/logout` 清除 cookie
   - 所有 8 個 `/api/admin/**` route(users、thresholds、audit-log、cvi-applications、health、risk-overview 及其 `[id]` 子路由)加上 `requireRole(request, ['admin'])` 檢查,沒有有效 admin session 一律回 401
2. **CVA 資格檢查 fail-open**——`/api/contracts/cva-eligibility/[address]` 在非 real 模式(包含忘記設定環境變數的情況)一律回傳 `eligible: true`,前端 `CvaEligibilityCard` 又完全略過 API 回傳的 `message` 欄位,導致「demo mode」的提示從來沒有顯示出來,畫面上只看到綠色「Eligible」。修法:API 回傳明確的 `mock: boolean` 欄位;前端在 `mock: true` 時改成琥珀色「Demo Mode」提示,不再跟真實驗證通過共用同一個綠色勾勾。
3. **`.env.example` 從未進 repo**——`.gitignore` 的 `.env*` pattern 把 `.env.example` 也排除掉了,改成只排除真的有密鑰的檔案,並把 `.env.example` 加回 git。

## 影響範圍

- 新檔案:`lib/auth/session.ts`、`lib/auth/requireRole.ts`、`app/api/auth/logout/route.ts`
- 修改:`app/api/auth/login/route.ts`、8 個 `/api/admin/**` route、`hooks/useRole.ts`(logout 呼叫新的 API)、`app/api/contracts/cva-eligibility/[address]/route.ts`、`components/shared/CvaEligibilityCard.tsx`、`.gitignore`
- 新環境變數:`SESSION_SECRET`(需加進 `.env.local` 才能登入,見 `.env.example`)

## 決策依據

Kenneth 收到評審回饋後確認要修這三項(第四項地址連結判斷為低優先,先跳過)。這不是為了改變已公布的比賽成績,是因為這個專案接下來還會被用在 portfolio / 給潛在合作對象看,這幾個缺口實際存在、也真的會被任何檢查程式碼的人看到。
