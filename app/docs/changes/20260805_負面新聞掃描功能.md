# 20260805_負面新聞掃描功能

## 變更摘要
在 Bank Case Detail 頁面新增「AI 輔助新聞掃描」區塊,對案件的出口商 / 買方公司名稱做一次 adverse media(負面新聞)搜尋,輔助審核人員判斷雙方是否有潛在爭議報導。**明確定位為輔助參考,不是正式 AML/制裁名單篩查的替代品**。

## 變更內容

### 1. 新增 API route:`app/api/ai/adverse-media/route.ts`
**Exa 搜尋 + AI 摘要/分類**的兩段式架構,AI 那段透過 [[20260805_AI_Provider抽象層與OpenRouter支援]] 的 `lib/ai` 統一出口呼叫(Claude 或 OpenRouter,依 `AI_PROVIDER` 決定),不直接綁 Anthropic。

- 比照 `app/api/ai/case/route.ts` 的既有模式:server-only,key 不外流
- **Step 1 — 讀取快取**:先查 `case_news_scans` 這個案件最新一筆記錄的 `searched_at`,如果有,傳給 Exa 當作 `startPublishedDate`(增量搜尋,只找上次掃描之後的新文章);沒有(第一次掃描)就用近 12 個月當範圍
- **Step 2 — Exa 搜尋**:呼叫 Exa 的 `/search` API(`type: 'neural'` 或 `category: 'news'`),查詢 `companyName`(出口商)與 `buyerName`(買方,若已存在,見 [[20260805_新增貿易融資案件欄位]]),取回候選文章的 title / url / publishedDate / snippet,不取全文
- **Step 3 — AI 分類/摘要**:把 Exa 回傳的候選清單丟給 `lib/ai`,要求判斷哪些看起來像負面/爭議性報導(訴訟、詐欺、制裁、財務危機等),沒有負面內容就明講「這次沒搜到新的負面報導」,不要硬湊
- **Step 4 — 寫入歷史**:把這次掃描結果(summary + sources,不存全文)寫成 `case_news_scans` 的新一筆記錄,`searched_at = now()`;舊記錄不覆蓋、不刪除
- 回傳格式:`{ summary: string, sources: { title: string, url: string, publishedDate?: string }[], searchedAt: string, isFallback: boolean }`,前端預設顯示最新一筆,並可展開看歷史記錄列表

**技術選型:為什麼用 Exa 做搜尋**
- Exa 是專門做語意搜尋的服務,可以用 `category: 'news'`、`startPublishedDate` 這類參數限定範圍與做增量查詢,結果比通用 web search 更容易篩到新聞類內容,也不綁特定 AI 供應商的帳號方案
- 拆成兩段(Exa 找候選 → AI 判斷)比讓單一 AI 邊搜邊寫結論更可控,之後想換搜尋來源只動 Step 2
- 需要新的環境變數 `EXA_API_KEY`(server-only,比照 API key 規則,只能在 API route 用),要麻煩 Kenneth 自己去 Exa 申請 key 並加進 `.env.local`

### 2. 資料庫 schema 新增:歷史快取表(新 migration)
新增 `case_news_scans` 表(不是加欄位在 `cases` 上,因為要保留完整歷史,一個案件會有多筆):
- `id`(uuid,pk)
- `case_id`(uuid,references `cases.id`)
- `searched_at`(timestamptz,not null)—— 這次掃描的時間,也是下次增量搜尋的起點
- `since_date`(timestamptz,nullable)—— 這次搜尋實際用的 `startPublishedDate`(第一次是 null,代表查全部)
- `summary`(text)—— AI 摘要,不存文章全文
- `sources`(jsonb)—— `{ title, url, publishedDate }[]`
- `ai_provider`(text)—— 這次用哪個 AI provider 生成摘要(`claude` / `openrouter:<model>`)
- 索引:`(case_id, searched_at desc)`,方便查「這個案件最新一筆」

### 3. Fallback
`lib/aiFallbacks.ts` 新增 `adverseMedia` 靜態文案,行為比照現有規則(AI 呼叫失敗/timeout → 顯示 fallback,不阻斷頁面,`isFallback: true`,且**不寫入** `case_news_scans`,避免快取到一筆空結果)

### 4. 前端顯示(`app/bank/cases/[id]/page.tsx`,搭配 [[20260805_案件詳情頁Tab化]] 的 News Scan tab)
- 進 tab 預設顯示上次掃描結果(讀 `case_news_scans` 最新一筆,不主動打 Exa/AI,不會每次進頁面都重查)
- 「Scan for updates」按鈕:手動觸發增量搜尋,按下才呼叫 `/api/ai/adverse-media`
- tab 頂部固定顯示一行小字警語:「AI-assisted scan of public news only — not a substitute for formal AML or sanctions screening.」
- 掃描歷史用簡單的時間軸列表呈現(比照 `CaseActivityTimeline` 的呈現方式),每筆顯示掃描時間 + summary + 來源連結
- 從未掃描過的案件顯示「Not yet scanned」+ 掃描按鈕

### 5. 已知限制(先講清楚,demo 時避免被問倒)
- Demo 用的公司名稱多為虛構/小型 mock 資料,真實網路上大機率搜不到任何新聞 —— 這是預期行為,不是 bug
- 不涵蓋制裁名單(OFAC/UN 等)、PEP 名單、法院資料庫,這些需要專門資料源(Refinitiv/Dow Jones 等),不在這次範圍內
- 改成手動觸發後,銀行審核人員如果沒按過「Scan」,畫面上就是「Not yet scanned」——這是刻意設計(省成本),但也代表不會主動提醒審核人員該掃了,之後如果要做「自動定期掃描」會是另一個獨立變更

## 決策依據
Kenneth 提出「查新聞確認雙方是否有潛在問題」的想法,方向與平台合規定位相符。但基於這是輔助工具、不能取代真正 AML 篩查,這次規格裡把定位和限制寫清楚(警語 + 已知限制),避免展示時被誤認為正式合規功能。

Kenneth 提議整合 Exa —— 改成 Exa 負責搜尋、AI(透過 `lib/ai` 可切換 Claude/OpenRouter)負責摘要/分類的兩段式架構,理由見上方「技術選型」。這個方向需要 Kenneth 自己申請 `EXA_API_KEY` 並加進 `.env.local` 才能動工。

Kenneth 進一步要求要有搜尋紀錄:保留完整歷史(而非只存最新一筆),但只存 AI summary + 來源連結,不存文章全文 —— 這樣歷史紀錄不會佔太多空間,也不會有版權疑慮(不轉存新聞全文)。下次掃描以「上次搜尋時間」做增量查詢,避免每次都全部重查、浪費 API 額度。同時把「每次進頁面自動搜尋」改成「手動按鈕觸發」,這是這次規格新增的行為改動,原本規劃是自動掃描,這裡一併記錄變更。

拿到 `EXA_API_KEY`、確認 [[20260805_AI_Provider抽象層與OpenRouter支援]] 的 provider 抽象層做完之後,再開始寫這份的程式碼。
