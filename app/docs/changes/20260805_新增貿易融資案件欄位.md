# 20260805_新增貿易融資案件欄位

## 變更摘要
Bank Case Detail 的 Case Information 卡片欄位太少(只有 Amount / Stage / Buyer Concentration / 時間戳記),不足以支援銀行審核。追加真正的貿易融資業務欄位,並修正一個既有 bug:`buyerName`、`invoiceNo` 其實已經在 Exporter Apply 表單收集、也送到 API,但 API 沒有存進資料庫,直接被丟棄。

## 變更內容

### 0. 修正既有 bug(優先)
`app/api/mock/cases/route.ts` 的 `POST` 目前只用 `buyerName`/`invoiceNo` 算 `invoiceHash`,沒有把這兩個欄位寫進 `cases` 表 —— 使用者填的資料進了 API request body,卻沒有真的存起來。這次一併補上。

### 1. 資料庫 schema 新增欄位(新 migration)
`cases` 表新增:
- `buyer_name`(text,nullable)—— 買方公司名稱(表單已收集,現在才真的存)
- `invoice_number`(text,nullable)—— 發票號碼(表單已收集,現在才真的存)
- `due_date`(date,nullable)—— 發票到期日/融資天期。real 模式下目前 `exporter/apply/page.tsx` 已經算了一個寫死 60 天的 `dueDate` 送上鏈,這裡把同一個值存回資料庫顯示用
- `currency`(text,not null,預設 `'USD'`)—— 目前 `formatUSD` 寫死美元,先加欄位為未來多幣別鋪路,這次 UI 仍固定顯示 USD
- `industry`(text,nullable)—— 產業別
- `buyer_country` / `exporter_country`(text,nullable)—— 國別

### 2. Exporter Apply(`/exporter/apply`)
Step 2「Buyer & Document Information」新增輸入欄位:
- Due Date(date picker,real 模式下預設帶入 mint 時使用的 60 天到期日,唯讀顯示;mock 模式可自由輸入)
- Industry(下拉選單,先給幾個常見產業如 Manufacturing / Textiles / Electronics / Agriculture / Other)
- Buyer Country / Exporter Country(下拉或文字輸入)
- Currency 先不開放使用者選,固定 USD,避免這次改動範圍擴大到金額換算邏輯

### 3. API
- `POST /api/mock/cases`:接住並寫入上述新欄位
- `PATCH /api/mock/cases/[id]`:允許之後補建/修正這些欄位(比照現有 per-milestone PATCH 的寫法)

### 4. 顯示
- `app/bank/cases/[id]/page.tsx` 的 Case Information 卡片加上 Buyer Name、Invoice Number、Due Date、Industry、Buyer/Exporter Country
- `app/exporter/status/[id]/page.tsx` 視情況同步顯示 Buyer Name / Invoice Number(目前完全沒顯示)

### 5. 型別
`types/case.ts` 的 `FinanceCase` 加上對應欄位;`lib/supabase/caseMapper.ts` 的 `CaseRow` / `mapRowToCase` 同步更新。

## 影響範圍
- `supabase/migrations/`(新檔案)
- `app/api/mock/cases/route.ts`、`app/api/mock/cases/[id]/route.ts`
- `app/exporter/apply/page.tsx`
- `app/bank/cases/[id]/page.tsx`、`app/exporter/status/[id]/page.tsx`
- `types/case.ts`、`lib/supabase/caseMapper.ts`

## 對應 PRD 章節
- 對應 Case Information 顯示範圍擴充,無新增頁面/角色權限異動

## 決策依據
Kenneth 反應 Case Information「感覺很少」。盤點後發現不只是「資料存在但沒顯示」,還有真正遺失的資料(buyerName/invoiceNo 被表單收集卻沒進 DB)—— 這次一併修正,並補上銀行審核實務上會需要的到期日/產業/國別欄位。Currency 欄位先加但不開放輸入,避免這次改動牽連到金額換算與 USD 顯示邏輯,之後有多幣別需求時再開一次獨立的 docs/changes。
