# 20260806_使用者管理真實化

## 變更摘要
`/admin/users` 目前完全唯讀,5 個帳號寫死在 `data/mockUsers.ts`。這次搬進 Supabase 一張新的 `users` 表,讓 admin 能真正編輯使用者(改角色/組織/錢包地址)、新增使用者、對非 demo 使用者重設密碼,並顯示每個使用者已成功 mint 的發票 NFT 數量。

**這是獨立於既有 `profiles` 表的新表**——`profiles.id` 綁死 `references auth.users(id)`,是留給以後真的接 Supabase Auth 用的,目前完全沒在用。這次做的 `users` 表是給現有「mock 登入」機制用的,不牽動 `profiles` 或任何依賴 `current_user_role()` 的 RLS 政策。

## 變更內容

### 1. 資料庫 schema:新增 `users` 表(新 migration)
```sql
create table public.users (
  id uuid primary key default gen_random_uuid(),
  email text not null unique,
  password text not null,        -- 明文，比照目前 mockUsers.ts 的既有安全等級，見下方「已知限制」
  role user_role not null,       -- 重用 init_schema.sql 已定義的 enum
  name text not null,
  organization text not null,
  wallet_address text,           -- admin 手動填，NFT 數量靠這個關聯
  is_seed boolean not null default false,  -- true = 5 個內建 demo 帳號，密碼不可透過 UI 重設
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```
Migration 同時把 `data/mockUsers.ts` 目前的 5 筆資料寫成 `is_seed = true` 的 seed rows,email/password/role/name/organization 完全比照現在的值,登入行為不會中斷。

### 2. 登入機制改為 server 端驗證
- 新增 `app/api/auth/login/route.ts`(server-only):接 `{ email, password }`,查 `users` 表比對,成功回傳去除密碼的使用者資料
- `hooks/useRole.ts` 的 `login()` 改成呼叫這支 API(從同步比對陣列改成 `async`),`sessionStorage` 存法不變
- `app/(auth)/login/page.tsx`、`components/shared/RoleSwitch.tsx` 呼叫 `login()` 的地方補上 `await`
- `data/mockUsers.ts` 保留,但只作為登入頁「Demo Accounts」快速按鈕和 RoleSwitch 元件的**已知公開展示帳號清單**,不再是驗證來源(這 5 組帳密本來就印在登入頁上給人示範用,不是機密)

### 3. `/api/admin/users` 從唯讀改成可管理
- `GET`:改查 `users` 表(取代查 `MOCK_USERS`),額外算出每個使用者的 NFT 數量:`select count(*) from cases where lower(exporter_wallet) = lower(users.wallet_address) and chain_tx_hash is not null`
- `POST`:新增使用者(email/password/role/name/organization/wallet_address),`is_seed` 固定 `false`
- `PATCH /api/admin/users/[id]`:編輯 name/organization/role/wallet_address;如果帶了新密碼且該筆 `is_seed = true` → 回傳 403 拒絕,錯誤訊息說明 demo 帳號密碼不可透過此介面變更

### 4. `/admin/users` 頁面
- 表格新增欄位:Wallet Address、NFT Count
- 每列加「Edit」(彈窗改 name/organization/role/wallet_address)、「Reset Password」(demo 帳號這顆按鈕直接不顯示或 disabled + tooltip 說明)
- 新增「Add User」按鈕(email/password/role/name/organization)
- 依 CLAUDE.md 規則 7,這幾個操作都要寫進 `/api/admin/audit-log`

## 已知限制
- 密碼明文存放,沒有 hash——這是延續目前 `mockUsers.ts` 本來就有的作法(甚至比現況好一點,因為現況密碼整包在前端 JS bundle 裡,這次改到 server 端比對後密碼不會再送到瀏覽器)。如果之後要正式上線而非 hackathon demo,這裡需要加 bcrypt/argon2 之類的 hash,這次先不做
- NFT 數量的關聯完全依賴 `wallet_address` 這個手動填寫欄位,admin 沒填就永遠是 0,不會自動偵測

## 對應 PRD 章節
- 對應 Admin 模組使用者管理範圍擴充,不影響其他角色頁面權限

## 決策依據
Kenneth 要求 `/admin/users` 要真正可以編輯/改角色/重設密碼/看 NFT 數量。討論後確認:密碼重設只開放給後續新增的使用者,5 個內建 demo 帳號維持不可從 UI 改密碼(避免 demo 帳密被改壞、影響其他人測試);NFT 數量比照「mint 成功即計入」的邏輯,直接算 `cases` 裡有 `chain_tx_hash` 的紀錄數,不用即時查鏈,减少一次額外的 RPC 呼叫。
