# 20261006_AI案件評估改手動並保留歷史

## 變更摘要
AI Case Assessment 不再於開啟案件頁時自動呼叫，改成使用者手動按「Generate / Regenerate Assessment」才產生，並把每次評估存下來，可回頭查看過去的評估。做法比照既有的 News Scan（`case_news_scans` + `NewsScanPanel`）。

## 變更內容
- **新增資料表** `case_ai_assessments`（migration：`supabase/migrations/20261006000000_add_case_ai_assessments.sql`）
  - 欄位：`id`、`case_id`（references `cases`）、`evaluation`（AI 評估全文）、`ai_provider`（`anthropic` 或 `openrouter:<model>`，例如 `openrouter:moonshotai/kimi-k2.6`）、`created_by`（觸發者 email，來自 session）、`created_at`
  - 每次產生新增一筆，不覆蓋、不刪除舊紀錄
  - RLS：bank / researcher / admin 可讀；寫入只走 service role（API route）
- **`app/api/ai/case/route.ts`**
  - `GET ?caseNumber=`：回傳該案件的評估歷史（新到舊）
  - `POST { caseNumber, caseData }`：產生評估並寫入歷史
  - 兩者都加上 `requireRole`：GET 允許 bank / researcher / admin，POST 允許 bank / admin（POST 會花 AI 額度）
  - AI 呼叫失敗或沒有 API key 時回傳 fallback 訊息，**不寫入歷史**（比照 News Scan：失敗不能被當成一筆真的評估）
  - 找不到對應的 Supabase 案件（例如純 mock 案件）時仍產生評估並回傳，但標示 `saved: false`，不寫入
  - 不改變 `CASE_AI_MODEL` 開關與 token 上限（維持 800）
- **`lib/ai/index.ts`**：`getCaseAi()` 額外回傳 `providerLabel`，供寫入 `ai_provider` 欄位
- **新增元件** `components/shared/AiAssessmentPanel.tsx`
  - 進入時只讀取歷史（不呼叫 AI）；沒有紀錄時顯示 Generate Assessment 按鈕，有紀錄時顯示最新一筆與 Regenerate Assessment 按鈕
  - 每筆顯示產生時間、使用的模型、觸發者；舊評估可展開查看
  - 失敗時顯示 fallback 提示，並說明這次沒有被儲存
- **頁面**：`app/bank/cases/[id]/page.tsx`、`app/bank/cases/page.tsx` 移除自動呼叫 `/api/ai/case` 與 `aiText` / `aiLoading` 狀態，改渲染 `AiAssessmentPanel`

## 決策依據
- 自動呼叫的問題：每次開頁面就花一次 AI 額度，結果無法保留，也無法重測；失敗時只看到 fallback，無從得知原因
- 評估是銀行審核的參考依據，保留歷史才能回溯「當時 AI 說了什麼」，與 News Scan、Travel Rule、audit log 的設計一致
- 每筆記錄使用的模型，Kimi bounty 的「核心功能由 Kimi 驅動」就有可查證的紀錄
- 已知風險：Kimi K2.6 是會思考的模型，思考 token 計入 `max_tokens`，800 的上限可能導致答案為空而退回 fallback。本次不處理（Kenneth 決定還原上限），手動按鈕讓失敗時可以重試；若持續失敗再另案調整
