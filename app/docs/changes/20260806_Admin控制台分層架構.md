# 20260806_Admin控制台分層架構

## 變更摘要
取代 [20260806_Admin平台控制台儀表板.md](20260806_Admin平台控制台儀表板.md) 的「全部塞一頁」規劃。改成分層架構:Dashboard 只看整體狀態、Case 詳情頁看進度(沿用既有頁面)、案件清單頁強化(錢包/tx hash/卡住標記)、新增「從使用者看狀態」的角色化視角,Admin 的「協助」定位為**唯讀診斷,不新增操作權限**。

## 分層架構

```
/admin (Dashboard)                    ← Layer 1：整體狀態，「有什麼事要處理」
  ├─ Stat 卡片（真實數字）
  ├─ Needs Attention（卡住案件 + 高風險企業，精簡列表，點了才跳轉）
  ├─ AI 今日風險總結
  └─ 快速導覽

/bank/cases (案件清單，bank + admin 共用)  ← Layer 3：全部案件，可篩選
  └─ 點案件 → /bank/cases/{id}          ← Layer 2：單一案件完整進度（已存在，不用重做）

/admin/users/{id} (新增)                ← Layer 4：從使用者看狀態
  └─ 依角色顯示對他有意義的案件/活動
```

## 變更內容

### Layer 1 — `/admin` Dashboard(改寫）
- Stat 卡片改接真實資料:`app/api/mock/stats/route.ts` 從寫死假數字改查資料庫既有的 `dashboard_stats` view,補 `overdueRate`(已撥款+已過期+未還款的比例)、`chainDataCoverageRate`(有 tx hash 的案件比例)、`avgProcessingDays`(已核准案件的處理天數平均)
  - **影響提醒**:`/bank/dashboard` 也呼叫同一支 API,Stat 卡片會一起變成真數字,這是預期中的改善
- 「Needs Attention」區塊:
  - 卡住案件:非 `approved`/`rejected` 且 `updatedAt` 超過 3 天沒變動(純前端算,用 `/api/mock/cases` 既有資料,3 天先寫死)
  - 高風險企業 + 新聞掃描:新增 `app/api/admin/risk-overview/route.ts`,查 `risk_level = 'high'` 案件並帶出 `case_news_scans` 最新一筆(沒掃過就顯示「Not yet scanned」,不會觸發新掃描)
  - 兩者都只顯示精簡列表(例如各 5 筆),點了直接連到 `/bank/cases/{id}`,不在 dashboard 展開
- AI 今日總結:重用既有 `/api/ai/dashboard`,把 stat 數字 + 卡住案件數 + 高風險案件數當 context
- 合約地址速查卡:純前端,顯示 `lib/contracts/config.ts` 的 `contractAddresses`,連到 Monad Explorer
- 順便把 `/admin/audit-log` 的 API(`app/api/admin/audit-log/route.ts`)從假資料改查真的 `audit_log` 表(`/admin/users` 的新增/編輯/重設密碼已經在寫真資料了)

### Layer 2 — Case 詳情頁
不用做任何事,`/bank/cases/{id}` 已經有 Case Information / On-Chain Activity / AI Assessment / News Scan 四個 tab,admin 本來就能進去看。

### Layer 3 — `/bank/cases` 案件清單頁強化(bank + admin 共用)
- 左側案件列表:每筆加「Stuck」小徽章(邏輯同 Layer 1 的卡住判定)
- 右側詳情面板(`CaseDetailPanel`):目前的 Invoice Details 卡片加上 Exporter Wallet / Buyer Wallet 兩個欄位(截斷 + 連 Explorer,比照 `bank/cases/{id}` 已有的 `HashField` 寫法)
- **刻意不**把完整的 On-Chain Activity / News Scan 搬進這個面板 —— 那些留在 `/bank/cases/{id}`(按「Full Page」進去看),避免同一套邏輯維護兩份

### Layer 4 — `/admin/users/{id}`(新增)
- `app/api/admin/users/[id]/route.ts` 補上 `GET`(目前只有 `PATCH`),回傳單一使用者資料
- 新頁面 `app/admin/users/[id]/page.tsx`:
  - 使用者基本資料(姓名/信箱/組織/角色/錢包地址,可以直接複用 Edit 彈窗)
  - **依角色顯示相關案件**:
    - Exporter → 查 `exporter_wallet` 符合的案件,顯示各案進度
    - Importer → 查 `buyer_wallet` 符合的案件,標出待確認/待還款的
    - Bank/Admin/Researcher → 這幾個角色在鏈上共用單一 `bankWallet`,無法歸屬到個別使用者,這裡先顯示「此角色不綁定特定案件」的說明文字,不硬做假資料
  - NFT mint 紀錄(這次從 `/admin/users` 列表隱藏的 NFT 數量,搬來這裡的使用者詳情頁顯示,列出實際 mint 的案件而不只是數字)

### Layer 5 — Admin「協助」的定位(唯讀診斷,不新增操作權限)
Admin 在這幾個畫面能看到「案件卡在哪一步、卡住幾天、卡在等誰(buyer/bank/exporter)」,以及該使用者的聯絡資訊(email),方便去提醒對應角色 —— 但 Approve/Reject/Disburse 這些動作**維持只有 bank 角色能做**,不修改 CLAUDE.md 現有的角色權限表。

## 影響範圍
- `app/admin/page.tsx`(改寫,範圍比前一版計畫小 —— 拿掉全案件表格)
- `app/bank/cases/page.tsx`(強化,加 Stuck 徽章 + 錢包欄位)
- `app/admin/users/[id]/page.tsx`(新檔案)
- `app/api/admin/users/[id]/route.ts`(補 `GET`)
- `app/api/admin/risk-overview/route.ts`(新檔案)
- `app/api/mock/stats/route.ts`、`app/api/admin/audit-log/route.ts`(mock → 真實查詢)

## 已知限制
- 卡住天數(3 天)先寫死
- Bank/Admin/Researcher 角色因為共用鏈上單一錢包,無法在 Layer 4 顯示「這個銀行行員審過哪些案子」這種歸因,是鏈上合約設計本身的限制,不是這次能解的

## 決策依據
Kenneth 釐清不需要把所有東西塞進一個 dashboard 頁面,而是要分層:Dashboard 看整體、Case 頁看單案進度(沿用既有頁面即可)、使用者頁看角色視角。Admin 的「協助」明確定調成唯讀診斷,不擴大操作權限,避免這次改動牽動 CLAUDE.md 的角色權限表。`/bank/cases` 列表頁選擇直接強化而非另建 admin 專用版本,因為 bank 跟 admin 都會受益,不用維護兩套邏輯。
