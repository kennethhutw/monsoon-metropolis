# 20261013_A-Token重新發行與合約重新部署

## 變更摘要
Cleanverse 回覆：CVA 不允許用不同的 App ID 管理，必須用目前的 App ID 重新發行 A-Token。因此用新 App ID 重新發行 A-Token，並以新的 stablecoin 地址重新部署三份合約。

## 變更內容
- 用目前的 `CLEANVERSE_API_ID`（`APP20260828…`）重新跑 `scripts/launch-atoken.ts`，取得新的 A-Token 地址
- 以新地址作為 `MOCK_USDC_ADDRESS`，重新部署 ComplianceRegistry / InvoiceAsset / FinancingPool（stablecoin 地址是 FinancingPool 的建構子參數，無法原地更換）
- 重新授予 MINTER_ROLE、鑄幣給 Bank、存入池子流動性、重新 onboard Exporter 與 Buyer
- 更新 `.env.local`、`Monsoon_contract/.env`、線上環境變數的合約地址
- **程式碼不變**，只有部署與設定；合約原始碼不修改（`disburse()` / `repay()` 的 CVI 檢查仍不在本次範圍）

## 影響範圍
- 所有合約地址（ComplianceRegistry、InvoiceAsset、FinancingPool、A-Token）
- 舊合約上的案件與 NFT 不會搬到新合約；資料庫 `cases` 裡指向舊鏈的案件（`invoice_token_id`、`financing_case_id`）在 real 模式下會對不上新合約
- 先前錄好的 demo 影片、`docs/one-page-summary.md` 與 README 裡的合約地址需要更新
- 舊部署記錄 `output/deploy_monadTestnet_202608021423.txt` 保留作為歷史

## 對應 PRD 章節
- 不對應 `Monsoon_App_PRD.md` 既有章節，屬於部署與設定變更

## 決策依據
- 主辦方明確指出舊 A-Token 與新 App ID 不相容，`verify_apass` 因此無法使用；重新發行是唯一讓 CVA 資格檢查恢復的做法
- Kenneth 已決定在截止前執行
- 風險控管：執行前備份 `.env.local` 與 `Monsoon_contract/.env`；新部署驗證通過（三個錢包的 `verify_apass` 回傳 eligible）之前，不切換線上環境變數

## 失敗時的退路
- 舊部署與舊環境變數保持原樣直到新版驗證通過；任何一步卡住，就停止並回到「誠實揭露 verify_apass 無法使用」的提交方式
