# 20260803_真實鏈上簽署完整流程

## 變更摘要
把 exporter apply → importer 確認收款 → exporter 送出融資 → bank 核准/撥款 → importer 還款,整條主線在 `NEXT_PUBLIC_CONTRACT_MODE=real` 時改成呼叫 `lib/contracts/walletActions.ts`,由使用者自己連接的錢包簽署,不再只是 Supabase 狀態變更。

## 變更內容

### 1. 資料庫 schema 新增欄位(新 migration,不改現有檔案)
`cases` 表新增:
- `invoice_token_id`(bigint,nullable)—— InvoiceAsset NFT 的 tokenId,mint 後才有值
- `financing_case_id`(bigint,nullable)—— FinancingPool 的 caseId,submitCase 後才有值
- `exporter_wallet`(text,nullable)
- `buyer_wallet`(text,nullable)

### 2. Exporter Apply(`/exporter/apply`)
- real 模式下,表單新增「Buyer Wallet Address」欄位(現在只有 Buyer Company Name,合約 mint 需要真實地址)
- 送出動作變成:先連錢包 → 呼叫 `walletActions.mintInvoice()` 拿到 tokenId → 把 tokenId/exporter_wallet/buyer_wallet 一併寫回 Supabase 那筆案件
- **不會**在這一步呼叫 `submitCase`(合約規定要等買方確認過)

### 3. 買方確認收款(新增,`/importer/payables` 加一個區塊)
- 目前這個頁面沒有「確認收款」這個動作,只有已核准案件的 Confirm Payment(還款)
- 新增「Pending Confirmation」區塊:列出 `buyer_wallet = 目前連接地址` 且尚未確認的案件,按鈕呼叫 `walletActions.confirmReceivable(tokenId)`

### 4. Exporter 送出融資申請(`/exporter/status/[id]` 加動作)
- 買方確認後,狀態頁出現「Submit for Financing」按鈕
- 呼叫 `walletActions.approveInvoiceTransfer()` 再呼叫 `walletActions.submitCase()`,拿到 financing_case_id 寫回 Supabase,案件狀態轉 `ai_review`

### 5. Bank 核准 / 撥款(`/bank/cases/[id]`)
- Approve 按鈕改呼叫 `walletActions.approveCase(financing_case_id, riskScore, ccpAuditHash)`
- 新增 Disburse 動作,呼叫 `walletActions.disburse(financing_case_id)`
- Reject 改呼叫 `walletActions.rejectCase()`

### 6. 買方還款(`/importer/payables`)
- Confirm Payment 改呼叫 `walletActions.repay(financing_case_id)`(需要先 approve USDC/mUSDC 給 FinancingPool,跟銀行存流動性時同樣的 approve 模式)

### 7. Mock 模式完全不受影響
上述全部只在 `isRealContractMode` 為 true 時生效,mock 模式維持現有「一路按到底」的簡化流程,demo 影片如果來不及接完整套,mock 模式隨時可以當備案。
