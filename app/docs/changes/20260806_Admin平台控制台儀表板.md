# 20260806_Admin平台控制台儀表板

## 變更摘要
把 `/admin`(目前只有系統健康狀態卡片 + 導覽連結)升級成真正的平台控制台:全部案件狀況、企業風險與還款、每個案件的錢包/交易 hash、合約地址速查、卡住案件偵測、風險企業 + 新聞掃描結果、AI 今日風險總結。

## 變更內容

### 1. Stat 卡片改接真實數字(目前是寫死假資料)
`app/api/mock/stats/route.ts` 目前回傳完全寫死的假數字(`pendingCasesCount: 127` 這種,不管資料庫實際狀態都不會變)。這次改接資料庫裡本來就存在、一直沒人用的 `dashboard_stats` view,並補上三個目前 view 沒有的欄位算法:
- `overdueRate`:`disbursed_at` 已設定 + `due_date` 已過期 + `repaid_at` 仍是 null 的案件比例
- `chainDataCoverageRate`:有 `chain_tx_hash` 的案件佔全部案件比例
- `avgProcessingDays`:已核准案件的 `updated_at - created_at` 平均天數

**影響提醒**:`/bank/dashboard` 也是呼叫同一支 API,這次改完後,那頁的 5 個 Stat 卡片會從假數字變成真數字 —— 這是預期中的正向改善,不是意外行為,但先講清楚以免你之後看到數字變了覺得奇怪。

### 2. 卡住案件偵測(純前端計算,不需要新 API)
`/api/mock/cases` 本來就回傳每個案件的 `stage`、`updatedAt`。在 `/admin` 直接用現有資料算:非 `approved`/`rejected` 的案件,`updatedAt` 超過 3 天沒變動 → 標記「Stuck」。3 天是先寫死的預設值,之後如果要讓 admin 自己調整,需要再開一次獨立變更(牽動 `thresholds` 表)。

### 3. 全部案件表格
直接用 `/api/mock/cases` 現有資料(已經包含 `exporterWallet`、`buyerWallet`、各階段 tx hash),欄位:
- Case # / Company / Buyer / Stage / Risk Score & Level / Amount
- Exporter Wallet、Buyer Wallet(截斷顯示,點開連 Monad Explorer,比照 `bank/cases/[id]` 已經有的 `HashField` 做法)
- Latest Tx Hash(從 mint/confirm/submit/approve/disburse/repay 這幾個 tx hash 欄位裡,取時間最新的一個)
- Stuck 徽章(有卡住才顯示)
- 點列可連到該案件的 `/bank/cases/{id}` 完整頁面(不重做一份案件詳情,直接連過去)

### 4. 新增 API:`app/api/admin/risk-overview/route.ts`
回傳 `risk_level = 'high'` 的案件清單,每筆帶上 `case_news_scans` 裡最新一筆掃描結果(如果有掃描過的話)—— 讓 admin 一眼看到「風險企業」+「這企業有沒有負面新聞」。這支只查資料庫,不會觸發新的 Exa/AI 呼叫(用既有掃描紀錄,沒掃過的就顯示「Not yet scanned」)。

### 5. 合約地址速查卡片(純前端,零新邏輯)
直接顯示 `lib/contracts/config.ts` 裡的 `contractAddresses`(ComplianceRegistry / InvoiceAsset / FinancingPool / Stablecoin),每個都用已經有的 `explorerAddressUrl()` 連到 Monad Explorer。

### 6. AI 今日風險總結
重用既有的 `/api/ai/dashboard`(不用新增 route),把 stat 數字 + 卡住案件數 + 高風險案件數一起送進去當 context,請 AI 用一段話總結「今天平台風險狀態」。跟 `/bank/dashboard` 現有的 AI Insights 邏輯一樣,失敗會走 fallback。

### 7. 順便接通 Audit Log(之前答應過的)
`/admin/audit-log` 目前也是純假資料陣列。這次 `/admin/users` 的新增/編輯/重設密碼已經在寫真的 `audit_log` 資料列了,順便把 `app/api/admin/audit-log/route.ts` 改成查真的表,`/admin` 頁面放一個「最近管理操作」的小清單。

## 影響範圍
- `app/admin/page.tsx`(大改)
- `app/api/mock/stats/route.ts`(mock → 真實查詢)
- `app/api/admin/risk-overview/route.ts`(新檔案)
- `app/api/admin/audit-log/route.ts`(mock → 真實查詢)
- `data/mockStats.ts`(保留當作型別定義用,不再是資料來源)

## 對應 PRD 章節
- Admin 模組儀表板功能擴充,不影響其他角色頁面權限

## 已知限制
- 卡住天數(3 天)先寫死,之後要做成可調整需要另開變更
- 「Latest Tx Hash」只從資料庫已存的 6 個里程碑欄位挑最新的,不會即時查鏈(跟這次新聞掃描的設計邏輯一致,避免每次進頁面都打 RPC)
- Risk overview 只看 `risk_level = 'high'`,不是即時重算風險分數

## 決策依據
Kenneth 要求 admin 要能看到全部案件狀況、企業風險與還款、每個案件的錢包與 tx hash、合約地址、卡住案件怎麼看、風險企業的新聞掃描結果、AI 風險判斷。盤點後發現大部分資料其實已經存在(`cases` 表的 wallet/tx 欄位、`case_news_scans`、`dashboard_stats` view、`contractAddresses`),這次主要是把這些既有資料整合到一個頁面,新增的邏輯只有卡住偵測、風險企業+新聞的組合查詢、以及把兩支原本純 mock 的 API(stats、audit-log)接上真實資料庫。
