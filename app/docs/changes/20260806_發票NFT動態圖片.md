# 20260806_發票NFT動態圖片

## 變更摘要
Exporter mint 發票 NFT 時,`metadataURI` 目前固定傳空字串,合約(`InvoiceAsset.sol` 的 `ERC721URIStorage`)雖然支援存 tokenURI 但沒有內容可存。這次幫每張發票 NFT 產生真正的 ERC-721 metadata(含依真實案件資料動態生成的 SVG 圖片),讓 MetaMask/區塊瀏覽器能顯示有意義的 NFT 圖片,而不是空白。

## 變更內容

### 1. 新增 API route:`app/api/nft-image/[invoiceHash]/route.ts`
- 依網址帶的 `invoiceHash` 查 Supabase `cases`(`invoice_hash` 欄位已是唯一索引),取出 company_name、buyer_name、amount、invoice_number、due_date
- 組一段 SVG 字串,回傳 `Content-Type: image/svg+xml`,內容包含 Monsoon 品牌樣式 + 這幾個欄位,做成類似「發票卡片」的視覺
- 查不到案件(理論上只會發生在 mint 完、`POST /api/mock/cases` 還沒寫入資料庫這極短的空窗期)→ 回傳一張通用的「Processing…」版本,不報錯

### 2. 新增 API route:`app/api/nft-metadata/[invoiceHash]/route.ts`
- 同樣依 `invoiceHash` 查案件,回傳標準 ERC-721 metadata JSON:
  ```json
  {
    "name": "Monsoon Invoice — INV-2026-0527",
    "description": "Tokenized trade receivable on Monsoon. Company: ..., Amount: $...",
    "image": "https://<domain>/api/nft-image/<invoiceHash>",
    "attributes": [
      { "trait_type": "Finance Type", "value": "Receivables" },
      { "trait_type": "Amount (USD)", "value": 100 },
      { "trait_type": "Buyer", "value": "Atlas Industrial Buyers Inc." },
      { "trait_type": "Due Date", "value": "2026-10-04" }
    ]
  }
  ```

### 3. `app/exporter/apply/page.tsx`
`mintInvoice` 呼叫時,`metadataURI` 從固定空字串改成 `${window.location.origin}/api/nft-metadata/${invoiceHash}`(`invoiceHash` 本來就是 mint 前用 keccak256 算好的,已知值,不用等鏈上回傳)。

## 已知限制
- **需要 app 部署在公開網址才看得到效果**。MetaMask / Monad Explorer 抓 tokenURI 時是伺服器對伺服器打這個 URL,`localhost` 它們連不到 —— 目前還沒部署 Vercel,這次改完程式碼是對的,但實際畫面要等部署後才驗證得了
- 圖片內容依賴 `cases` 表的資料,如果之後這筆案件的 company_name 等欄位被修改,圖片內容也會跟著變(沒有做「鑄造當下截圖凍結」),這對 demo 沒差,但不是嚴格意義的「不可變 NFT 圖片」

## 影響範圍
