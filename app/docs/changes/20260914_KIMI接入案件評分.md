# 20260914_KIMI接入案件評分

## 變更摘要
讓 `AiCompleteParams` 支援每次呼叫指定 model，並新增一個開關，讓 AI 案件風險評分（`/api/ai/case`）可以切換成用 Kimi K2.6（透過 OpenRouter）驅動，滿足 Metropolis hackathon「Best Builds Powered by KIMI」bounty 對「meaningfully driving a core feature」的要求。

## 變更內容
- `lib/ai/types.ts`：`AiCompleteParams` 新增 `model?: string`（可選，不影響現有呼叫）
- `lib/ai/openrouter.ts`：`complete()` 改用 `params.model ?? process.env.OPENROUTER_MODEL ?? DEFAULT_MODEL`，允許呼叫端覆寫 model
- `lib/ai/anthropic.ts`：不需要改（結構化型別，多餘欄位不影響現有實作）
- `app/api/ai/case/route.ts`：新增 `CASE_AI_MODEL` 開關（`default | kimi`，比照 `RPC_PROVIDER` 的模式）
  - `default`（不設定時）：行為完全不變，走現有 `aiClient`（依 `AI_PROVIDER` 決定 Anthropic 或 OpenRouter）
  - `kimi`：這條路由改成直接呼叫 `openrouterClient`，model 寫死 `moonshotai/kimi-k2.6`，不受全域 `AI_PROVIDER` 影響
  - 兩種情況下都保留原本的 fallback 邏輯（沒有對應的 API key 時回傳 `AI_FALLBACKS.case`，不噴錯誤給使用者）
- `.env.example`：新增 `CASE_AI_MODEL=default`（server-only，非 `NEXT_PUBLIC_`）

## 影響範圍
- `lib/ai/types.ts`
- `lib/ai/openrouter.ts`
- `app/api/ai/case/route.ts`
- `.env.example`
- 不影響 `/api/ai/dashboard`、`/api/ai/risk`、`/api/ai/alerts`、`/api/ai/adverse-media` 這幾條路由，它們繼續走原本的全域 `AI_PROVIDER` 開關

## 對應 PRD 章節
- 不對應 `Monsoon_App_PRD.md` 既有章節，屬於本次 hackathon 新增能力，記錄在 `docs/hackathon-metropolis-plan.md` 工作項目（KIMI bounty）

## 決策依據
- Metropolis hackathon KIMI bounty 要求「meaningfully driving a core feature, not bolted on as a chatbot widget」——AI 案件風險評分是 Monsoon 的核心功能之一（銀行審核時參考的建議），比新增一個裝飾性 chatbot 更站得住腳
- 比照 `RPC_PROVIDER`（Alchemy 那次）的「switch，不整個換掉」模式：預設行為不變，只有明確設定 `CASE_AI_MODEL=kimi` 才會啟用，避免在沒有充分驗證 Kimi 輸出品質前，就永久改變這個核心功能的預設行為
- Kimi 透過 OpenRouter 存取（`moonshotai/kimi-k2.6`，$0.58/$3.40 per M tokens），跟現有 `OPENROUTER_API_KEY` 走同一組設定，不需要新的 SDK 或帳號
- Kenneth 已向 Moonshot 詢問過 hackathon 專屬 credit，回覆是活動結束後才能申請——此次先用一般 OpenRouter 額度支付，成本低，不是阻礙
