# 20260731_錢包連接與真實鏈上簽署

## 變更摘要
在 `NEXT_PUBLIC_CONTRACT_MODE=real` 時,exporter/bank/importer 三個角色改用自己連接的 MetaMask 錢包對合約簽署交易(mintInvoice / submitCase / confirmReceivable / approveCase / disburse / repay),不再是後端代簽。

## 變更內容
- 安裝並設定 `wagmi` + `@rainbow-me/rainbowkit`(已在 package.json,目前未接線)的 Provider,鏈設定指向 Monad Testnet(chainId 10143)
- 新增「Connect Wallet」UI(放在 Nav 或各角色 dashboard 頂部),顯示已連接地址、鏈別是否正確(非 Monad Testnet 顯示切換提示)
- Mock 模式不受影響 —— 錢包連接只在 `CONTRACT_MODE=real` 時才會出現/生效,mock 模式維持現有 email/password demo 帳號流程
- `lib/contracts/real.ts` 中原本標記「pending wallet-connect UI」的 5 個函式(`mintInvoice`/`submitCase`/`approveCase`/`disburse`/`repay`)改為接受一個 viem `WalletClient`(從前端 wagmi hook 取得),不再全部用 server-only admin key
- 受影響頁面:
  - `/exporter/apply`(送出申請 → 呼叫 mintInvoice + submitCase,需要 exporter 錢包已連接且該地址已有 CVI)
  - `/exporter/kyb`(顯示「on-chain address」時改顯示真實連接的地址,而非 mock 假地址)
  - `/bank/cases/[id]`(Approve/Reject/Disburse 按鈕改為需要 bank 錢包簽署)
  - `/importer/payables`(Confirm Payment / Repay 改為需要 importer(buyer)錢包簽署)
- CVI 核發(registerCVI,admin-signed)維持不變 —— 這是平台動作,不受此變更影響

## 影響範圍
- 上述 4 個頁面的互動流程(real 模式下多一個「請先連接錢包」的前置狀態)
- `lib/contracts/real.ts`、新增 `lib/wagmi.ts`、`components/shared/ConnectWalletButton.tsx`(新檔案)
- `hooks/useContract.ts` 可能需要改為接受 wagmi 的 walletClient

## 對應 PRD 章節
- 對應 hackathon-demo-plan.md 的 Phase B(App 整合四階段規劃)

## 決策依據
合約用 `msg.sender` 判斷身份與權限(exporter 自己 mint 自己的 invoice、bank 專屬地址才能 approve/disburse、buyer 專屬地址才能 confirm/repay)。若全部用後端同一把 key 代簽,鏈上會看起來像「同一個地址扮演所有角色」,跟 Monsoon「每個參與者有自己 CVI 綁定錢包身份」的核心賣點矛盾,評審也可能認為只是資料庫加假鏈上日誌。Kenneth 確認要走真正的 wallet-connect(而非後端代管 demo 錢包),即使會增加 demo 錄製與時程風險。
