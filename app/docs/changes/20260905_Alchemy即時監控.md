> **狀態（2026-09-08）**：程式碼已完成並保留，但決定不啟用。`RPC_PROVIDER` 預設 `default`，`.env.local` 未設定 `ALCHEMY_API_KEY`，行為與改動前完全一致。若之後要啟用，只需申請 Alchemy API key 並設定 `RPC_PROVIDER=alchemy`，不需要再改程式碼。

## 變更摘要
把 `/admin/health` 從 100% mock 資料改成用 Alchemy 做真實的鏈上連線與服務健康檢查，同時符合 Metropolis hackathon「Best Projects using Alchemy」bounty 的整合要求。

## 變更內容
- 新增 Alchemy RPC 呼叫，實際 ping 鏈上節點連線狀態，取代目前寫死的 `sepoliaConnected: false`
- 欄位命名 `sepoliaConnected` 目前跟實際部署鏈（Monad Testnet）對不上，本次一併改成不綁定特定鏈名稱的命名（例如 `chainConnected`），避免繼續沿用舊命名造成混淆
- Claude API 健康檢查是否從「只檢查環境變數是否存在」升級成實際發一次輕量測試呼叫，待決定（有成本/延遲的取捨，見下方待確認）
- `SystemHealth` 型別可能需要新增欄位標示資料來源（real vs mock），避免真假資料混在一起被誤讀

## 設計定案（討論後確認）

**Alchemy 支援 Monad Testnet**（`https://monad-testnet.g.alchemy.com/v2/API_KEY`），前提成立。

**改用 switch 方式，不整個換掉現有 RPC**——比照現有 `AI_PROVIDER=anthropic|openrouter` 的模式：

```bash
RPC_PROVIDER=default   # default | alchemy，預設 default，行為完全不變
ALCHEMY_API_KEY=xxxx   # server-only，不可加 NEXT_PUBLIC_ 前綴
```

**範圍限定在 server 端，不動錢包連線：**

- ✅ `lib/contracts/config.ts` 的 `publicClient`（server 端讀取，`/admin/health` 用這個）——依 `RPC_PROVIDER` 切換
- ❌ `lib/wagmi.ts` 的 `wagmiConfig`（瀏覽器端錢包連線/送交易）——**完全不動**，維持現在的 `NEXT_PUBLIC_MONAD_RPC_URL`

理由：`wagmiConfig` 在瀏覽器執行，如果也套用 switch，Alchemy API Key 就得曝露成 `NEXT_PUBLIC_`，跟現有 codebase 嚴格區分 server-only/`NEXT_PUBLIC_` 的原則不一致；錢包連線是使用者實際操作、demo 當天會被點到的路徑，不動它可以降低風險。`ALCHEMY_API_KEY` 保持 server-only，跟 `ANTHROPIC_API_KEY` 同等級保護。

**`/admin/health` 回傳內容調整：**

- `sepoliaConnected: boolean` → 改成不綁鏈名的欄位（例如 `chainConnected`），並改成真的呼叫 `publicClient` 做一次輕量讀取（例如 `getBlockNumber()`）來判斷連線狀態，取代寫死的 `false`
- 新增 `rpcProvider: 'default' | 'alchemy'` 欄位，讓頁面本身就能顯示目前用的是哪個 provider——這也是 demo 當天要展示 Alchemy 有被實際用到的關鍵欄位
